- Added `install.ps1`, a native Windows installer that resolves the release version, verifies the npm tarball SHA-256, installs it globally, prepares uv for the Python kernel, and updates the user PATH, plus Windows setup documentation and a Windows CI job.
- Fixed uv auto-install on Windows: the kernel bootstrap now drives the Windows PowerShell uv installer instead of the POSIX `curl | sh` pipeline, which failed with `spawn sh ENOENT`.
- Fixed the Windows batch shim dropping empty arguments: `cmd.exe` leaves `%NAME%` unexpanded when the variable value is empty, so empty values are now passed as an empty quoted pair.
- Fixed the supervisor relaunch lock on Windows: the lock path was derived from the supervisor socket, which is a named pipe, so it resolved inside the `\\.\pipe\` namespace where no lock file can be created.
- Made the Windows test surface runnable: Windows-aware fixtures for the tools-manager probes, `core.autocrlf=false` in the destructive-git guard repo, TESTS spill-directory env, `mkdirSync` instead of the POSIX `mkdir` binary, a `file://` hook URL for `--import`, and a documented skip for POSIX mode-bit assertions.
- Windows tool-path hardening: `killProcessTree` uses absolute System32 `taskkill` with an error listener, environment merging folds keys case-insensitively on win32, and Git Bash discovery also covers the per-user install root that non-elevated Git for Windows installations use.
- Windows no longer needs a POSIX shell: the shell tool defaults to Windows PowerShell (then `ComSpec`), PowerShell commands are wrapped so native exit codes survive, `shellPath` is classified per shell instead of assuming POSIX, and the tool description names the real shell.
- Fixed the direct worker transport on Windows: `getDaemonSocketIdentity` returned `undefined` for named pipes, so every `get_direct_worker_transport` request failed and an interactive session could not attach.
- Hardened `%USERPROFILE%\.prime` with a Windows ACL (`icacls` inheritance removal plus an owner-only grant) because mode bits are not access control on Windows.
- Converted the bundled skills and skill docs from bash to PowerShell/Python examples.
- The kernel's `bash()` also runs without a POSIX shell on Windows: it resolves Windows PowerShell then cmd.exe (never PATH), takes its status from a wrapper line instead of the POSIX status fd, and reports the command's own exit code; the resolving host now selects the same shipped shell for the kernel and the shell tool, so Git Bash is used only when `shellPath` names it.
- Fixed the release packer on Windows: it spawned the `npm` shim directly, which Node cannot execute, so every pack failed; it now runs npm's JavaScript entry point through the current runtime, and ships `install.ps1` beside `install.sh`.
- Fixed `install.ps1` on Windows PowerShell 5.1, where `Invoke-WebRequest.Content` can be a byte array and the version lookup crashed on `.Trim()`.
- Made the destructive-git dirty-tree guard shell-aware: it builds relocation probes in the syntax of the shell that runs them (PowerShell `Set-Location -LiteralPath`/`$env:`, cmd `cd /d`/`set`, POSIX unchanged) and recognizes each family's relocation forms, refusing conservatively where a location change cannot be replayed.
- Completed the kernel `bash()` Windows support: the PowerShell wrapper runs from a temporary script instead of `-Command` text, so a cmdlet error names the user's own line instead of echoing probe internals; the status probe tolerates a non-numeric `$LASTEXITCODE` and no longer glues probe text into user output; and the POSIX-only tests are marked with explicit reasons while the remaining tests run in the selected shell.
- Fixed Windows daemon discovery: `scanListeningDaemons` returned nothing because it relies on `ss`/`lsof`/`ps`, so `prime-agent doctor`, `ps`, and `status` reported no background services and `shutdown --force` claimed success while the daemon kept running. Windows now reads the durable supervisor-owner registry, counts a record only while its process identity (pid plus start id) still matches, and reports a live-but-unidentifiable process as `unverified` instead of silently succeeding. That stale daemon also held native modules open, which made `npm uninstall/install -g prime-agent` fail with EBUSY.
- Publish the Windows installer: the release workflow now renders and uploads `install.ps1` and `install-beta.ps1` for both channels and prints their URLs. A new `check:installer-ps1` check (part of `npm run check`) gates the render contract the beta upload depends on, the HTTPS default, the checksum use, and parses the file with a real PowerShell where one exists.
- Added a Windows CI workflow that builds, type checks, runs the installer check and the Windows-compatible test files, and runs the kernel runtime suite on Windows.
- Added a cross-platform `testSocketPath` fixture helper and used it in the daemon-launch fixtures: Windows accepts only a named pipe under `\\.\pipe\`, so a POSIX-style `join(tmpdir(), "d.sock")` endpoint fails with EACCES, the fixture's listen callback never fires, and the test hangs until its timeout. `test/daemon-launch.test.ts` now passes 30/30 on Windows and the run exits cleanly, so it is part of the Windows CI list.
- Converted five more daemon test fixtures to the cross-platform endpoint helper (`daemon-peer-transport`, `daemon-routed-client`, `daemon-agent-connection-reconnect-park`, `proper-lockfile-compromise`, `suite/regressions/6006-bundled-bedrock`): on Windows they used a POSIX-style socket path, which `listen` rejects with EACCES, so ten tests timed out. All five files now pass on Windows and are part of the Windows CI list. One lease-compromise assertion is marked POSIX-only, because a named pipe has no path to lease and the code returns undefined on win32 by design.
- Made the `!command` config fixtures platform-aware: `src/core/resolve-config-value.ts` runs them through the resolved shell, which is Windows PowerShell on win32, so `!printf ...` and `!... | tr` fixtures failed there. Commands are now built per platform with the same assertions, the POSIX-only owner-only-mode assertion is skipped on win32 where mode bits are not permissions, and `auth-storage` plus `model-registry` pass 145/145 on both platforms.
- Added `install.ps1 -Uninstall` (and `-PurgeData`): it stops the background service before npm removes the package, so the daemon no longer leaves native modules locked, and documents the manual equivalent.
- The CLI now explains the print-mode fallback on Windows when the terminal is MinTTY, MSYS, or Cygwin, instead of silently ignoring the request for the interactive UI.
- Windows daemon and view tests: `daemon-mode` (six fixtures awaited a listen callback that Windows never calls for a POSIX path), `daemon-supervisor-eviction`, `package-self-update-daemon`, `agents-view-mode`, `agents-view-state` and the four `repl-kernel-*` files now use platform-aware endpoints, paths, and venv layouts. `daemon-mode` alone hung forever on Windows and blocked the whole suite; it now completes in 39 s.
- Kernel-provisioning tests are honest on Windows: they fake the interpreter, uv, or a helper with `#!/bin/sh` scripts, which Windows cannot execute (the product spawns the interpreter directly, and a `.cmd` shim needs a shell). 54 fixture-dependent tests are marked POSIX-only with a reason; 12 that do not need a fake still run, and all 76 still run on Linux.
- Small Windows test fixes: POSIX mode-bit assertions in `migrations` and `telemetry` are skipped on win32 (where the ACL hardening replaces them), `release-workflow` cleans its temp directory best-effort on win32, and its three bash-workflow-step tests are POSIX-only because Windows resolves `find.exe`/`tar.exe` from System32.
- Update-path tests are platform-correct: `config-native-update` loads its fixture loader as a file URL (a bare Windows path is rejected by the ESM loader) and expects the download fallback on win32, where no install is installer-owned; `native-update` builds its link target with `join` so `readlink` matches, asserts the ownership refusal on win32, and marks the one test that needs a native update *plan* POSIX-only, since no standalone Windows archive exists.
- Autonomous quality gates now run in the same shell as the agent's own shell tool instead of the platform default (`shell: true`, i.e. `cmd.exe` on Windows), so a gate command means the same thing in both places; the exit code is the command's own on every platform, and the cmd.exe fallback keeps Node's verbatim-quoting behaviour.
- Gates honour the `shellPath` setting like the shell tool does, and the Windows support status (including the npm-tarball route, the PowerShell shell, and what is not available on Windows) is documented.
- `$VISUAL`/`$EDITOR` now handles paths with spaces (the normal Windows case): the command is parsed with quote awareness and the executable is spawned directly, with a shell fallback for a Windows `.cmd` shim, and a failure is reported to the user instead of silently keeping the old text.
- Daemon, package-manager and journal tests on Windows: nine files used POSIX-style listen endpoints, `${sessionDir}/` prefixes, `spawn("sleep")` fixtures or an un-normalized owner record; all now use platform-aware endpoints or normalized comparisons. Two real win32 defects were fixed: `normalizeSocketPath` only lower-cased, so `//` spellings never compared equal and a relative socket stayed relative; and the supervisor compared a raw persisted path with a normalized one, silently ignoring persisted host settings.
- `bun` joined the Windows shell-command list, because a user-scoped bun install is a `.cmd` shim that libuv cannot spawn directly; the two bun self-update tests now run and pass on Windows instead of being POSIX-only.
- The remaining tail (agents view identity literals, auth flow isolation, output accumulator temp vars, suspend platform pinning, session-manager disposal, mode-bit assertions) is platform-correct: 21 Windows failures became 0, and Linux counts are unchanged.
- Two more real Windows defects: the daemon catalog child passed a bare Windows path to `node --import`, which the ESM loader rejects (`ERR_UNSUPPORTED_ESM_URL_SCHEME`), so the catalog process could never start; it now passes a file URL. The fs.watch regression test spawned `npx` (a `.cmd` shim that Node cannot execute without a shell) and imported a module by a bare Windows path; it now uses the Node runtime with tsx's resolved path and a file URL.
- The last platform-test tail: config-directory isolation sets USERPROFILE as well as HOME, POSIX-style socket paths use the endpoint helper, a lower-cased socket path is compared case-insensitively, temp-dir cleanup in the suite harness is best-effort on win32, and the two intermittent supervisor-monitor tests were made deterministic (fake timers were running the availability probe against real lockfile I/O). Two POSIX-only fixtures (a fake shebang interpreter and a fake shell) are skipped on Windows with reasons.
